# DeepSequence T20I: Final Academic Report

## Introduction
The use of data analytics in professional sports has completely changed how teams plan their strategies and choose their players. In cricket, the Twenty20 (T20) format relies the most on data because it is very fast and unpredictable. Unlike traditional Test cricket which lasts for five days, a T20 match only has 120 balls per team. Because the game is so short, every single ball is extremely important to the final result. In recent years, professional teams have spent a lot of money on data analysis to get an advantage over their opponents. However, the current tools used by coaches and TV broadcasters have a major flaw: they mostly focus on what happened in the past, rather than predicting what will happen next. Traditional stats usually just show a batsman's career strike rate or a bowler's overall economy rate, which does not explain how much pressure the player is facing in the current live match.

DeepSequence T20I was created to fix this problem by building a system that predicts the future based on the current "momentum" of the game. Our project uses a massive historical database containing over 1.2 million balls bowled across more than 5,600 official T20 International matches. Instead of just looking at static career averages, our engine looks at the exact situation happening right now. It calculates the pressure created by the last few balls, the current phase of the match, and how well the two batsmen at the crease play together. By turning these situations into math, the software can predict the exact percentage chance of the next ball being a wicket, a dot ball, or a boundary. This report explains the problems we are trying to solve, how we built the software, the technologies we used, and how much it would cost to use this system in the real world.

## Problem Statement

**The core problem this project solves is that traditional cricket analytics rely on static career averages that fail to measure the changing momentum of a live match, leading teams to make multi-million dollar tactical decisions based on flawed, outdated data rather than real-time mathematical predictions.**

The creation of DeepSequence T20I solves a major problem in both the social and technical sides of the sports industry. From a social and business view, professional cricket teams spend millions of dollars buying players based on basic stats or simply human guessing. Coaches often have to make very stressful decisions during a match—like picking which bowler should bowl the final over—based purely on their gut feeling rather than solid evidence. Relying on human guessing when millions of dollars are on the line is a big weakness for any team. There is a strong need for an objective, data-driven tool that can calculate the pressure of a match and give coaches real-time probabilities to help them make better decisions.

From a technical view, the project solves several difficult computer science challenges. The biggest flaw in existing cricket models is that they cannot understand "momentum." For example, if a batsman has a high career strike rate of 150.0, a basic computer model will always assume he is about to hit a boundary. However, this is mathematically incorrect if the batsman has just faced five dot balls in a row during a very close run chase. In that situation, the "scoreboard pressure" makes the batsman panic, which greatly increases the chance that he will play a bad shot and get out. Traditional models do not have the memory to understand this changing pressure. 

Another technical problem is that historical cricket data is very messy and hard to read. While numbers like runs and wickets are easy to find, important tactical details—like where the ball bounced (Length) or what direction it was bowled (Line)—are usually hidden inside sentences typed by human commentators. Extracting this hidden data from normal text and turning it into numbers that a machine learning model can read is a very difficult Natural Language Processing (NLP) challenge. 

Furthermore, predicting cricket outcomes is hard because the data is unbalanced. In any T20 match, dot balls and singles happen much more often than wickets or sixes. Standard machine learning models get confused by this; they will often just predict a "single" for every single ball to make their accuracy score look high, even though that is useless to a coach. Finally, processing all this data is a big software engineering challenge. Searching through 1.2 million historical records to find specific player matchups requires a lot of computer power. If the code is slow, the dashboard will freeze, making it completely useless for a coach sitting in a fast-paced dugout.

## Project Description
DeepSequence T20I is a complete machine learning dashboard and data processing engine designed to solve these technical and sporting problems. The system works by downloading the entire open-source Cricsheet T20I dataset, organizing over 1.2 million ball-by-ball records into a fast, local database. The frontend of the project is an interactive web dashboard where an analyst can type in what is happening in the live match and instantly get predictive feedback based on historical data and momentum math.

The brain of the project is built on something called a 56-Dimensional Tensor. To accurately predict what will happen on the next ball, our engine cannot just look at one simple stat. Instead, for every ball in the sequence, the system calculates 56 different tactical features. These features include flags to show the current match phase (Powerplay, Middle Overs, Death Overs), codes that represent the specific bowling style of the opponent, and special numbers that track historical strike rates. 

To fill this tensor with tactical data, our project uses a Natural Language Processing (NLP) module. Because historical databases do not have clean columns for where the ball pitched, the NLP module reads thousands of raw text commentary sentences. By searching for specific keywords (for example, reading the phrase "banged in short and wide"), the code automatically groups historical balls into strict categories for Line and Length. Turning normal text into structured data is extremely important so the predictive algorithms can understand specific bowler tactics.

Another very important feature of the project is the Historical Partnership Strength module. Most cricket stats only look at one batsman at a time, ignoring the fact that they always bat in pairs. Our engine runs advanced database queries to see how well the active Striker and Non-Striker have historically played together. It calculates exactly how many matches they have played as partners, how many runs they score together, and how often they get out. This data is turned into a single Partnership Score. If the two batsmen historically play very well together, the score mathematically lowers the Striker's risk level. On the other hand, if the two players usually struggle to score when batting together, the engine artificially adds "scoreboard pressure" into the math, raising the chance of a wicket.

Equally important is how the system analyzes the bowlers. Instead of just looking at a bowler's overall career economy rate, the DeepSequence engine breaks down their performance into highly specific, tactical chunks. The dashboard requires the user to input both the Target Bowler (the person bowling right now) and the Supporting Bowler (the person bowling from the other end). This allows the math to calculate if pressure is being built from both ends of the pitch. Furthermore, the engine calculates "Bowler Suppression Metrics." It searches the 1.2-million-row database to see exactly how well the target bowler performs during specific match phases. A fast bowler might have a great record during the Powerplay when the ball swings, but struggle heavily during the Death Overs. The system also calculates the bowler's specific weaknesses against Left-Handed versus Right-Handed batsmen. It even groups bowlers into sub-styles (like Left-Arm Fast or Right-Arm Leg Spin) to cross-reference exactly which bowling styles cause the most trouble for the active Striker. All of this data ensures the bowler is treated as a dynamic, highly-detailed tactical threat rather than just a single name.

Finally, the project uses a Continuous Momentum engine to look at the up to 12-ball (two-over) sequence that the user typed in. Instead of using basic yes/no logic, the engine uses fluid math based on the run-rate of the last few balls. If the last few balls only scored very few runs, the algorithm detects a negative momentum shift, which sharply increases the risk level for the next ball. The final math results are shown on the dashboard as simple progress bars. These bars show the exact percentage chance of the next ball being a Wicket, a Dot Ball, 1-3 Runs, a Boundary, or a Six. The dashboard also has detailed tabs showing heatmaps of a batsman's weaknesses and a bowler's strengths based on the massive 1.2-million-row database.

## Technologies Used
The DeepSequence T20I platform was built using a modern and powerful technology stack focused around the Python 3 programming language. Python was chosen as the main language because it has the best libraries for data science and machine learning, allowing us to easily connect the database, the complex math, and the web dashboard all in one place.

For the Storage Layer, the project uses SQLite. Because our dataset is so huge (1.2 million rows), saving the data in basic CSV text files would force the computer to load hundreds of megabytes into its memory every single time it ran, which would crash the system or make it extremely slow. SQLite provides a fast, self-contained database engine. By indexing the most important columns (like Match ID, Striker, and Bowler name), complex searches and data grouping operations are done natively in the C-language in just milliseconds. 

Data manipulation and structuring are handled by a Python library called `pandas`. When the SQLite database returns the raw search results, Pandas is used to format this data into the multi-dimensional arrays needed by the mathematical engine. Pandas is highly optimized and can perform math across huge datasets instantly, which was necessary for calculating custom features like the Partnership Synergy scores.

The frontend user interface is built entirely using the Streamlit framework. Streamlit allows developers to quickly build interactive web applications directly using Python, meaning we did not need to write separate code for HTML, CSS, or JavaScript. However, Streamlit works by running the entire Python script from top to bottom every single time the user clicks a button. To stop the system from running heavy database searches 1.2 million rows deep every time a user moves a slider, the project heavily uses Streamlit’s `@st.cache_data` feature. This caching technology saves the output of a function directly in the computer's RAM memory after it runs for the first time. Any future clicks will just load the saved data instantly from memory, which makes the UI incredibly fast and keeps the CPU usage very low.

To make sure the historical data stays accurate over time without a human needing to update it manually, the project uses automated background scripts. Using Python's `subprocess` and `urllib` tools, a separate script is scheduled to run automatically every week in the background (using a Cron Job). This script downloads the newest international matches played that week, extracts the data, and uses smart logic to only insert the brand-new balls into the SQLite database. Finally, we used standard Python string manipulation tools (like the `re` regular expression module) to build the Natural Language Processing engine, which allowed us to extract the keywords needed to read the unstructured cricket commentary.

## Cost Analysis
A major advantage of the DeepSequence T20I software is that it is incredibly cost-efficient to run. If this system were to be used in the real world by a professional sports team, a national cricket board, or a live television network, the startup cost and monthly running costs would be extremely low compared to the expensive, proprietary sports analytics tools currently on the market.

The main reason it is so cheap is that we exclusively used open-source software and open data. The entire technology stack—which includes Python, SQLite, Pandas, and Streamlit—is completely free and open-source. There are no expensive software licenses, no royalties to pay, and no need to buy expensive database subscriptions (like Oracle or Microsoft SQL Server) to run the code. Furthermore, the massive historical dataset is downloaded directly from Cricsheet, a community-driven database that provides all the ball-by-ball data completely free of charge. This allows the team to completely avoid paying the massive monthly fees that commercial sports data companies usually charge.

Because the application uses a lightweight SQLite file instead of a massive database cluster, the hardware requirements are very low. The only thing the team needs to pay for is a cloud server to host the Streamlit web dashboard. To make sure the memory caching feature works perfectly when multiple coaches are using the app at the same time, the host server just needs a decent amount of RAM memory, rather than expensive graphics cards (GPUs). Hosting the application on a standard, mid-level cloud computer—such as an Amazon Web Services (AWS) EC2 `t3.medium` server or a Google Cloud server—would provide plenty of power. 

The estimated cost to run this cloud server 24 hours a day, 7 days a week, is only about $20 to $40 per month. Therefore, the total cost to keep the DeepSequence T20I engine running for a full year would be under $500. When you compare this $500 cost to the millions of dollars professional teams spend on buying players and hiring traditional data consulting firms, the economic return on investment for using this automated tactical engine is incredibly high.
